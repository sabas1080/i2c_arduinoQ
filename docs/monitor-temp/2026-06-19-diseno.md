# Diseño — App de monitoreo de temperatura en modo kiosko (Arduino UNO Q)

**Fecha:** 2026-06-19
**Autor:** Sabas Jimenez (diseño asistido)

---

## 1. Objetivo

Construir una **aplicación de monitoreo de temperatura** sobre el Arduino UNO Q
(QRB2210 + STM32, Debian 13) que:

- Lee un **sensor I2C** conectado al header/Qwiic.
- Muestra la lectura en la **pantalla del Arduino GIGA Display Shield** (panel DSI
  ST7701 480×800) con un número grande y color de estado.
- Permite **ajustar el umbral de alerta por touch** (GT911) y reconocer la alarma.
- **Registra las lecturas a CSV** para revisión/exportación posterior.
- Arranca en **modo kiosko**: sin pedir login, a pantalla completa, sin teclado.

> No se incluye gráfica histórica en esta versión (excluida explícitamente por el
> usuario; el CSV cubre el análisis posterior).

## 2. Contexto verificado del device

Comprobado por SSH en un UNO Q de fábrica (kernel 7.0.0, Debian 13 trixie):

| Pieza | Estado | Implicación |
|---|---|---|
| Sesión gráfica | LightDM + Xorg + XFCE corriendo | Hay escritorio; el "login" inicial es el greeter de LightDM |
| Navegador | `/usr/bin/chromium` instalado | Kiosko vía `chromium --kiosk` sin instalar nada |
| App Lab | `/usr/bin/arduino-app-cli`, `/usr/bin/arduino-cli` | Soporta app híbrida sketch + Python + bricks |
| Autologin | `lightdm.conf` soporta `autologin-user` | Se salta el login **sin teclado** |
| I2C header/Qwiic | Cableado al **STM32**, expuesto vía bridge RPC | El sensor se lee desde el sketch, no desde Linux directo |
| DSI + touch GT911 | **No activos** en device virgen | **Prerrequisito**: correr `scripts/enable-gigadisplay-shield.sh` |

**Camino de datos del header I2C:** en la UNO Q el I2C de los headers/Qwiic llega al
STM32 (no al SoC). El SoC habla con el STM32 por el bridge (MessagePack RPC). Por eso
el sensor se lee desde un **sketch** y el dato cruza al lado Linux por el bridge.

## 3. Arquitectura (Enfoque A — App Lab nativo)

```
[Sensor I2C @ Qwiic] --Wire1--> [Sketch STM32]
                                   | Bridge.provide("read_temp")
                                   v
                          [Programa Python (Linux)]
                                   |  - lee temp por bridge (poll ~1 Hz)
                                   |  - compara contra umbral -> estado ok/alerta
                                   |  - escribe CSV (timestamp,temp,umbral,estado)
                                   |  - sirve estado al web_ui + recibe acciones
                                   v
                    [web_ui brick]  <--HTTP/WS-->  [Chromium --kiosk localhost]
                                                         | en display DSI del shield
                                                         v
                                                   touch GT911 (como mouse en X)
```

### Unidades y responsabilidades

1. **Sketch STM32 (`sensor.ino`)** — única responsabilidad: leer el sensor por
   `Wire1` y exponer la lectura cruda por el bridge.
   - `Bridge.provide("read_temp", ...)` devuelve grados °C (float).
   - Sin lógica de UI ni de umbral; solo hardware + bridge.

2. **Servicio Python (`main.py`)** — orquesta:
   - Poll `Bridge.call("read_temp")` cada ~1 s.
   - Mantiene estado en memoria: `temp_actual`, `umbral`, `estado` (ok/alerta),
     `alarma_reconocida`.
   - Persiste cada lectura a CSV (append) en una ruta configurable.
   - Expone el estado al `web_ui` y atiende acciones del touch
     (`subir_umbral`, `bajar_umbral`, `reconocer_alarma`).

3. **Interfaz `web_ui` (HTML/CSS/JS del brick)** — solo presentación:
   - Número grande de temperatura + fondo/indicador de color según estado.
   - Botones grandes táctiles **[ − ] [ + ]** para el umbral y **[Reconocer]**.
   - Refresca el estado desde Python (polling o websocket que provea el brick).

4. **Capa de kiosko (config del sistema)** — no es código de la app:
   - Autologin de LightDM para `arduino`.
   - Autostart de Chromium en kiosko apuntando a la URL del `web_ui`.
   - "Run at startup" de la app en App Lab para que el backend levante en boot.

### Configuración (un solo lugar)

Constantes al inicio de `main.py` (o un `config.yaml` simple):
`I2C_ADDR` del sensor, `POLL_SEG`, `UMBRAL_INICIAL`, `PASO_UMBRAL`, `CSV_PATH`.

## 4. Flujo de datos y estados

- **Lectura:** Python llama `read_temp` → obtiene °C → actualiza `temp_actual`.
- **Evaluación:** si `temp_actual >= umbral` → `estado = alerta`; si baja del umbral
  (con pequeña histéresis, p.ej. 0.5 °C) → `estado = ok` y se limpia
  `alarma_reconocida`.
- **UI:** verde = ok, rojo/parpadeo = alerta. Si `alarma_reconocida`, el rojo deja de
  parpadear pero sigue marcando alerta hasta que la temp baje.
- **Touch:** [+]/[−] mueven `umbral` en pasos de `PASO_UMBRAL`; [Reconocer] setea
  `alarma_reconocida=True`.
- **Registro:** cada poll escribe una fila CSV `ts_iso,temp,umbral,estado`.

## 5. Manejo de errores

- **Sensor no responde / bridge falla:** Python captura la excepción, marca
  `estado = sin_dato` (UI en gris con "—"), reintenta en el siguiente poll. No
  crashea ni escribe basura al CSV (escribe `estado=sin_dato`, temp vacía).
- **STM32 reiniciando:** el bridge puede tardar; el poll usa timeout y degrada a
  `sin_dato` en vez de bloquear la UI.
- **CSV no escribible:** loguea el error una vez y sigue mostrando en pantalla (no
  abortar el monitoreo por un fallo de disco).
- **Chromium se cae:** el autostart lo relanza (o XFCE lo reabre); documentar el
  watcher si se decide usar uno.

## 7. Prerrequisito obligatorio: touch + pantalla

Antes de la app, en el device destino correr el bootstrap del propio repo para
levantar DSI + touch (no están activos en un device virgen):

```bash
ssh arduino@<IP>
sudo bash scripts/enable-gigadisplay-shield.sh   # tras copiarlo al device
# Verificar:
ls /sys/class/drm/card0-DSI-1/status              # connected
lsmod | grep -E "goodix|st7701"                   # ambos cargados
timeout 5 evtest /dev/input/eventN                # eventos ABS_MT al tocar
```

## 8. Pruebas / verificación

- **Sketch aislado:** flashear y verificar `read_temp` devuelve valores plausibles
  (tocar el sensor, ver que sube).
- **Python aislado:** correr `main.py` con un `read_temp` simulado (mock del bridge)
  → confirmar lógica de umbral, histéresis y CSV sin hardware.
- **web_ui:** abrir la URL en Chromium normal, probar +/−/Reconocer con mouse, luego
  con touch.
- **Kiosko end-to-end:** reiniciar el device → debe llegar solo a la app a pantalla
  completa, sin login, touch operativo.
- **Errores:** desconectar el sensor en caliente → UI a "sin_dato", reconectar →
  vuelve a leer.

## 9. Riesgos / abiertos

- **API del brick `web_ui`** (mecanismo y puerto): confirmar al inicio (§6).
- **Sensor concreto:** el diseño es agnóstico; definir chip/dirección y librería
  Arduino (ej. un Modulino Thermo u otro sensor I2C). Afecta solo a `sensor.ino`.
- **Relanzado de Chromium** si se cae: decidir si se añade un watcher simple.
- **Coexistencia App Lab "Run at startup" + autostart de Chromium:** validar el orden
  de arranque (backend listo antes de que Chromium cargue la URL; si no, Chromium con
  reintento/refresh).
